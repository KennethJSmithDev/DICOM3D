## Smallest provider-neutral plan — proposed, not implemented

Reuse CompDocs `InterSystems-2026/OpsDeck-Health/{MODEL_PROVIDER_PLAN,DICOM_AI_ARCHITECTURE,API_SURFACE_PLAN}.md` and existing AIStudyPlan/AIStudyResult schemas. No provider imports in the renderer. No AI in the public safe demo. No DICOM ingestion work.

1. **AI-C02 contract gate, no model required:** specify `describeCapabilities()`, `prepare(sourceRef, operation, policy)`, `execute(prepared, request)`, `status(executionId)` and `normalize(resultRef)`. Semantic and spatial operations remain explicit capability IDs, not one generic accuracy claim. Use synthetic recorded fixtures for contract/error tests, clearly labeled without pretending inference happened. No service or runtime deployment is needed for this gate.
2. **Opt-in companion module:** propose an independently installed `dicom3d-ai` package referencing the compatible viewer package, containing orchestration/result-reference code only. Do not add a mandatory AI dependency to core. Existing IPM supports packages/dependencies/lifecycle; a general Optional flag was not established. Avoid newer PythonWheel features on qualified IPM0.10.5-SNAPSHOT. Provider execution stays external to the renderer; choose remote versus isolated local only after rights/hardware approval. AI Hub build154 is a separate optional orchestration target, not a prerequisite for UI work.
3. **Policy before prepare/execute:** explicit operation, classified source reference, provider resolution, requested prompts, preprocessing ID, egress authorization and evidence policy. Enforce missing egress policy as false in code; JSON Schema defaults do not enforce it. Fail before transmission when rights/runtime/capability are unresolved. No browser-held provider credentials; no public write API.
4. **Provenance/result contract:** extend the plan (not current schemas yet) to require model asset/checkpoint hash or immutable hosted deployment ID, runtime and preprocessing identity, input hashes, prompts/parameters, timestamp and execution ID. Store arrays/masks as provider-owned payload references, not canonical identity fields. States QUEUED/PREPARING/RUNNING/SUCCEEDED/DEGRADED/FAILED/CANCELLED/UNOBSERVABLE remain explicit. Validate matching operation/provider/source references and resource limits, not merely JSON syntax.
5. **Separate qualification gate:** acquire only the chosen exact distribution after authorization; independently hash bytes/terms, measure preprocessing/runtime/latency/peak memory/transfer cost on permitted fixtures, exercise failures/cancellation, and qualify package lifecycle/security on a dedicated target. No local AMD/CUDA/CPU performance claim yet. BiomedParse v2 needs ~4.46GB checkpoint storage; this is not peak RAM/VRAM.
6. **Viewer boundary:** consume only reviewed normalized result references, separately labeled derived/unvalidated. Preserve accepted canonical POSITION/indices, semantic IDs, source transforms and H000. A mask requires independent frame/affine reconciliation before overlay; no automatic conversion into accepted anatomy or clinical evidence. Embeddings are not geometry.

Acceptance for future implementation: core works with module absent; no calls on page load; unapproved egress denied; deterministic provenance/source checks; unsupported operation reported honestly; failures cannot mutate source; optional module uninstall leaves no package-owned residue; cost measured against unchanged controls. No model activation or publication is authorized by this plan.
